# Development Plan

Milestones follow GDD Part 11 in exact order. No milestone starts until the previous one meets its completion
condition **and has been checked in Unity by you**. Status key: ✅ done · 🔶 code written, awaiting your Unity test · ⬜ not started.

## Decisions to confirm (please reply if you disagree)
These are defaults I chose because the GDD leaves them open. None changes a core design decision.
1. **Unity 6.3 LTS (6000.3.8f1).** LTS gives the longest support. **Built-in renderer for now.** URP (better mobile
   visuals) will be added once builds are proven stable, because adding it headlessly is riskier.
2. **Landscape-only orientation.** Standard for first-person mobile games and gives the trading UIs room.
3. **Legacy input for now.** The Input System package will be added later. The input code already supports both.
4. **No PC: builds run on Unity Build Automation** from GitHub, and you test the APK on your phone. Scene content is
   generated by editor scripts instead of being placed by hand. This works for early milestones but gets hard for
   art, lighting and level layout, so plan to get access to a computer before Milestone 5.
5. **Currency name "coins"** (as used in the GDD examples).
6. **Edit-mode unit tests** for all economy/transaction maths, which the GDD requires. These need no scene to run.

## Milestone 1: Shop prototype ✅ (superseded by v0.3.0; camera, input and interaction carried forward)
Implemented: `CameraController` + `LookMath` (DPI-scaled look, yaw ±100°, pitch −35°…60°), `TapDetector`,
`IInteractable` + `InteractionController` (centre-of-screen focus + tap-to-use), `CounterInteractable`,
`ShopHUD` built from `UIFactory`/`UITheme` (money, rank, customer status, Inventory/Upgrades/Travel, contextual
Interact button, crosshair, toasts, counter panel), `SafeAreaFitter`, `ShopSceneController`, and a generated
greybox shop (`ShopSceneBuilder`): enclosed room, door, counter with props, two shelf units, display table,
portal device, placeholder materials, warm lamps.

Original plan:
**Objective:** player stands behind the counter, looks around and interacts with the counter.

Planned implementation:
- `Player/CameraController`: reads `IPlayerInput.LookDelta`. Yaw clamped to about ±100° and pitch to about ±60°, so the player
  can't look at the wall behind them by accident. Sensitivity scaled by screen DPI so it feels the same on every phone.
- `Interaction/IInteractable` + `Interaction/InteractionController`: raycast from the screen centre (and tap-to-select
  on touch); highlight the looked-at object; on interact call `Interact()`.
- `Shop/CounterInteractable`: first interactable. Opens a placeholder counter panel.
- `UI/ShopHUD` (uGUI, Canvas Scaler set to scale with screen size, reference 1920×1080): money (placeholder 0),
  rank, Inventory / Upgrades / Travel buttons (disabled stubs), contextual Interact button.
- Shared UI style: one colour palette, font, button prefab (dark wood/brass "ledger" look, no glow or gradients).
- Simple greybox shop blockout: counter, back shelves, door, portal device placeholder, lighting pass.
- Tests: camera clamp maths, interaction target selection.

**Completion condition:** enter shop, look around, interact with the counter (GDD).
